# Каталог материалов

Публичный статический каталог: https://uks-design.github.io/materials-catalog/. Посетители могут искать и открывать материалы без регистрации. Карточки, опубликованные для всех, находятся в `materials.js`; доступ к их изменению определяется правами на репозиторий GitHub, а не интерфейсом сайта.

## Личный редактор

На компьютере владельца дважды нажмите `start-editor.bat`. Он запустит редактор только на этом компьютере и откроет `http://127.0.0.1:8766/editor`. Node.js должен быть установлен. Окно сервера оставьте открытым во время работы; закрытие окна остановит редактор. Папка `editor/` и файл запуска намеренно не входят в публичный репозиторий и не попадают на GitHub Pages.

1. Выберите карточку слева или нажмите «Новая карточка».
2. Измените поля, при необходимости приложите файл и нажмите «Сохранить карточку». Изменения пока только на вашем компьютере.
3. Откройте GitHub Desktop, выберите репозиторий `materials-catalog`, проверьте изменения `materials.js` и, если прикладывали файл, папку `files/`.
4. Сделайте Commit и Push origin. После успешной публикации GitHub Pages обновит общий сайт.

Редактор создаёт резервные копии `materials.js` в `.editor-backups/`. Они остаются только на этом компьютере. Файлы размером до 25 МБ сохраняются в `files/` и после Push становятся общедоступными. Не загружайте конфиденциальные материалы. Для больших файлов или Google Slides используйте ссылку на внешнее хранилище; права доступа к нему задаются отдельно. Удаление карточки не удаляет приложенный файл автоматически.

Редактор работает только на `127.0.0.1`, использует временный ключ сессии и не публикует ничего сам. Не открывайте порт 8766 наружу и не копируйте редактор на публичный хостинг.

## Перед публикацией

`materials.js` пока содержит демонстрационные карточки без ссылок на реальные файлы. Замените их утвержденными материалами и проверьте, что описания и ссылки можно показывать всем в интернете. Сам репозиторий и GitHub Pages не подходят для хранения секретов и непубличных файлов.

## Локальный запуск

Для просмотра публичной части без редактора в этой папке запустите любой локальный HTTP-сервер, например:

```powershell
python -m http.server 8080
```

Затем откройте `http://localhost:8080`.

## Публикация через GitHub Desktop

1. Войдите в GitHub Desktop под учетной записью GitHub.
2. Выберите `File` -> `Add local repository` и укажите **эту папку**. Локальный Git-репозиторий и первый коммит уже созданы. Не выбирайте родительскую папку `gj` или весь каталог `Codex`.
3. Проверьте список файлов и нажмите `Publish repository`. Для бесплатного GitHub Pages оставьте флажок `Keep this code private` выключенным: репозиторий должен быть публичным. Сайт будет общедоступным.
4. На GitHub откройте `Settings` -> `Pages`, выберите `Deploy from a branch`, ветку `main`, папку `/(root)` и сохраните.
5. После публикации GitHub покажет адрес вида `https://USERNAME.github.io/REPOSITORY/`. Проверьте поиск, фильтры и открытие карточек по этой ссылке.

## Кто может добавлять материалы

Посетители сайта не могут публиковать карточки. Владелец репозитория может пригласить доверенных редакторов через `Settings` -> `Collaborators` -> `Add people`. Редакторы с доступом на запись меняют `materials.js` в GitHub или через GitHub Desktop; после коммита и публикации обновления появляются у всех. Для обязательного согласования изменений настройте защиту ветки `main` с pull request и проверкой владельца.

Для добавления и редактирования используйте личный редактор. Если правите `materials.js` вручную, после `window.MATERIALS =` должен идти массив в синтаксисе JSON. Для кнопок в карточке укажите публично доступные `viewUrl` и/или `downloadUrl`; без них сайт покажет «Ссылки пока не добавлены». Проверьте права доступа к самим файлам отдельно: публичная ссылка на каталог не открывает закрытый файл Google Drive.

Карточки, созданные в старом прототипе, остаются в `localStorage` исходного браузера и помечены «Только в этом браузере». Они не попадают на GitHub автоматически; их данные нужно перенести в `materials.js` перед общим запуском.
